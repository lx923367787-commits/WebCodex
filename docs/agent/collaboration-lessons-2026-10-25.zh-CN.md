## 实际踩坑与处理

| 问题 | 根因与改进 | 验收边界 |
| --- | --- | --- |
| 已保存团队设置，聊天仍显示零额度 | 设置属于文件夹项目，聊天绑定命名项目。项目卡复用原设置；新身份固定唯一已授权文件夹、Host、策略及预算，目录和派发链路同步核对。 | 旧聊天不追溯扩权；多文件夹不猜执行目标。 |
| 调度器新安装无法启动 | 读取凭据前要求数据库及 sidecar 已存在，初始化顺序相互依赖。新增显式首次初始化，并拒绝覆盖已有状态。 | 不删除数据库、停止状态或旧失败记录来“恢复”。 |
| 宿主 CLI 能用，隔离调用却报告未登录 | CodeBuddy 包漏带区域配置，账号被发往不同服务；Antigravity 缺少匹配的隔离认证与配置映射。增加受审版本、完整包摘要、最小私有认证副本及原生加载方式。 | 不把适配失败直接归因于用户账号；宿主成功不等于 Runner 成功。 |
| 代理可用，隔离任务仍连接失败 | Runner 未读取已启用的 Windows 系统代理；回环授权还要求控制端权限。补充本机代理发现和启动前权限检查，继续使用每 Job 的授权日志与清理。 | 不固定端口、不改系统代理；仅接受受支持的无凭据数字回环 HTTP 代理。 |
| 登录刷新在隔离环境失败 | CodeBuddy 需要邻接锁文件及原子替换。仅本次执行的私有凭据叶目录可刷新，进程树停止后有界清理。 | 不向宿主登录源写回，不扩大其他任务或祖先目录权限。 |
| 多行任务、成员说明或空 effort 被拒绝 | 把正文当身份 key 校验；把不同 CLI 的 effort 当同一种必填参数。正文改用有界文本校验，身份仍严格；计划支持实际 effort/null 及事务内解析 `project_policy`。 | 精确模型与保存策略仍需匹配；没有支持证据就不添加 `--effort`。 |
| 网页卡片和应用标记识别过严 | 大小写、空白、已有应用标记和描述式授权卡导致误判。修复识别与标记复用，保留当前应用、会话和允许操作边界。 | 家庭插件名称不写死到共享默认；Computer Use 的 URL 检查失败不是 WebCodex 原生启动链路失败的证明，该外部问题不宣称已修复。 |
| 预检失败后无法可靠重试 | 失败回执缺少阶段及是否跨过发送边界的信息。只对明确未发送的预检失败做有界恢复；模糊或已发送结果不能盲目重发。 | 不清除旧回执、不重复领取身份；仅严格未发送预检恢复可续本地准备期限，单次运行/观察的绝对截止时间不随进展重置。 |
| 交接后身份仍在，却无法访问原项目文件 | 继任 run 的 Goal/assignment 与命名项目文件适配器未完整贯通。逐次核对当前身份、唯一 Goal、精确授权目录、Runner 所有者和实际固定目标。 | 保留敏感路径、撤销授权、只读策略、SHA 覆盖和不确定写结果检查。 |
| CLI 退出正常，但没材料、没产物 | 隔离工作区不能读取宿主源码，旧调用只传任务文字。计划冻结有界 `inputs`，生成快照/hash 后送入 stdin；显式发布文件及 manifest，再收集、读取版本并审核。 | 退出码 0、诊断 marker、存在文件都不是正式交付验收。 |
| 超时、旧执行和 blocked Goal 永久挡住后续工作 | 缺少保留历史的追加轮次与精确收尾识别。新增本地维护端有限追加轮次，修复原生后代停止证明和 blocked 原生交接；失败 Worker 的产物可独立审核。 | 不将 Failed 改为成功；不补充原重试预算；停止证据不确定时不能启动新轮绕开。 |
| 新预算上限让历史策略无法读取和修正 | 把新准入规则放进了通用结构校验。后续项目管理增量将两者分离：历史策略仍可读取和修改，新保存、新计划检查最低预算可满足性。 | 旧计划按原策略版本冻结；不因升级隐式扩大既有聊天权限。 |

## 源码覆盖范围

- Desktop/管理 CLI：命名项目入口、原文件夹团队设置、当前 Host 的受信目录管理。
- Store/Server：策略与执行目标关联、成员正文、可选 effort、输入快照、有限追加轮次、不可变审查和精确交接收尾；命名项目文件适配器是这条链路的必要依赖。
- Runner/Process/Core：受审 CLI 版本与包加载、最小认证映射、动态代理、私有刷新清理、输入 stdin 和 manifest 错误分类。
- Windows 工具：首次初始化、预检阶段、未发送恢复、应用识别和 blocked 原生接续。

整合以远端 `3fd8b24c` 为基线，保留已存在的每机安装说明、独立模型执行器排除和打包防护。没有把旧本地文件整体覆盖回远端。排除本机强制 CLI launcher、固定家庭连接名、一次性真实账号诊断测试、安装程序/二进制、游戏文件和 `.local` 回执。生产中的版本/程序/包摘要属于安全准入约束，不能当成本机杂项删除或放宽。

## 跨电脑调用方式

先按[外部工具与账号说明](../EXTERNAL_TOOLS.md#简体中文)分别安装、登录和配置。查询目标机实际 CLI 版本、模型及推理选项，再显式传递；帮助目录不证明账号额度可用。项目、Host、Tunnel、浏览器 profile、扩展授权、Runner 资源及账户选择都在目标机重建。

Node CodeBuddy 的目录查询使用管理员资源 profile 的 `codebuddy_config_directory`，必须是目标机的绝对目录，并参与资源审核摘要；不再隐式借用某个固定安装目录的账号配置。Node 映射缺少该字段时拒绝，不回退到另一个账号。旧 Node 资源需按本机目录重新审核；该字段不是模型工具输入，也不包含凭据内容。它只选择元数据查询配置，业务执行仍使用原有受控凭据复制机制，不是任意账号切换入口。

代理端口按目标机实际配置发现，不复制测试电脑端口。模型 CLI、网页扩展和 ChatGPT 的登录是不同的认证边界。更新工具 schema 后，应核对实际 callable 参数；客户端保留旧签名时不能以绕过验证或伪造值解决。`effort: "project_policy"` 只在精确策略版本、provider 和 model 匹配时解析，初始计划与追加轮次使用同一规则。

正式交付的字段、范围、停止证据和轮次调用见 [Windows 协作运行说明](../../windows/HOME-DEVELOPMENT.zh-CN.md#协作测试发现与通用修复)。浏览器子任务继续使用原生团队工具及明确发现的 thinking profile；不要把额外电脑操作验证变成整条链路的无关前置条件。
